# 需求 #162 补 /api/delete 级联清除下游共享记录 page_shares

- 状态：进行中（任务 306 开发已交付 c006722，审查中）
- 来源：thread_id=0; message_id=11701（用户指令）

## 背景

需求#160（共享书签）已验收关闭，但契约与实现有缺口：ENGINEERING.md（3faace9）第 49 行约定「来源删除文件（/api/delete）时同步 DELETE 下游共享记录，避免同名重传被旧幂等记录挡住」；实际 auth-server.js /api/delete（约 1243-1253 行）只删 page_display_names，未删 page_shares。前端虽以 source_exists=false 失效态兜底，但同名重传后旧幂等记录仍挡新记录，created_at 陈旧。主人拍板：补后端级联清除。

## 范围

- 包含：①/api/delete 删除文件后同步删除下游 page_shares 记录（WHERE source_tenant_id=来源 AND filename=被删文件）；②补回归用例（删除后共享记录清除、同名重传新记录生效）；③核对 ENGINEERING.md 契约与实现一致。
- 范围外：不改前端失效态逻辑；不处理需求#161 路径穿越事项。

## 验收标准

1. 来源删除文件后，该文件对应的下游 page_shares 记录被清除（GET /api/shared 不再返回）；
2. 同名重传后接收方再打开页面，page_shares 重新记录且 created_at 为最新时间；
3. 既有测试回归全绿；
4. page_display_names 删除行为不变。
